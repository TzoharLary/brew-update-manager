# ספקים עתידיים — המלצה מבוססת ראיות, 19.10.2026

המלצת התכנון היא מערכת גילוי משותפת עם מסלולי אימות שונים לכל ספק, וסביבת ברירת מחדל נפרדת לכל כלי או פרויקט. אין ספק אחד שמבטיח את כל החבילות, גרסאות היעד, הספריות והשירותים ל־Intel Tahoe. מה שקיים היום צריך להישמר כנתון מתוארך; חבילת catalog אינה התקנה מוכחת.

| ספק | שימוש מתאים | כיצד מגלים גרסה ותאימות | היכן ההבטחה נגמרת |
|---|---|---|---|
| Pixi + conda-forge | CLI מבודד; סביבת Python/C/C++ עם גרף ספריות שלם | מיפוי שמות מפורש, subdir `osx-64` ו־`noarch`, גרסת יעד/major, metadata של תלות; פתרון ללא התקנה, lock עם URL/hash ובדיקת הרצה בהמשך | אין התחייבות שכל חבילה קיימת או מתעדכנת בקצב upstream. Noarch לבדו אינו מוכיח שכל התלויות זמינות ל־Intel. ספריות בסביבה אינן מחליפות `/usr/local` אוטומטית. |
| uv + PyPI | CLI של Python או סביבת פרויקט Python | Python ABI וגרסה מפורשים; התאמת wheel ל־x86_64 או universal2; כל התלויות חייבות wheel מתאים במדיניות ללא בנייה | uv תומך Intel, אך מפרסמי החבילות יכולים להפסיק לפרסם wheels ל־Intel. דוגמה נוכחית: cryptography 50.0.2. Pycairo צריך גם Cairo; חבילת sdist אינה מסלול בינארי. |
| קובץ רשמי מהמפרסם | כלי שיש לו artifact מפורש ל־darwin-x64/x86_64 או universal | adapter לפי מוצר: release, artifact, OS מינימלי, ארכיטקטורה, checksum/signature, מטא־דאטה חתימה ותכולה | אין דרך כללית להניח שכל release כולל macOS Intel. LLVM 23 מציג רשמית macOS ARM64 בלבד; Whisper 1.9.5 ללא assets; merve מצרף מקורות בלבד. מתקין pkg/DMG עשוי לדרוש תכנון נפרד מנתיב shim. |
| MacPorts | מוצר/פרויקט שיכול לעבור כולו ל־prefix `/opt/local`; פתרון משלים כשאין conda/native | Portfile ושם port/variants/גרסה; להרחיב את כל הגרף ולבדוק ארכיון לכל צומת עבור Darwin 25 x86_64 ו־prefix הרגיל | קיום ארכיון לראש הגרף אינו מוכיח סגירה. בלי מדיניות binary-only הספק עשוי לנסות בניית מקור. שירותים וספריות דורשים מעבר צרכנים, תצורה ונתונים. |
| Homebrew | מלאי קיים, קבלות, תלות והמשכיות של צרכנים; בניית מקור רק במסלול מפורש | מטא־דאטה נוסחה ובקבוק עבור host, מצב קג/קבלה, build/runtime deps וסיבת עדכון upstream או revision | Intel הוא Tier 3, ללא בניית bottles חדשים לפי המדיניות הנוכחית; יכולת הרצה צפויה להסרה בספטמבר 2027 או אחריו. אין להסתמך עליו כספק בינארי לטווח ארוך למחשב הזה. |

הבסיס למסלולים:

- conda-forge מונה `osx-64` בין הפלטפורמות הראשיות. בפברואר 2026 העלה את ברירת המחדל המינימלית ל־macOS 11, עם חריגות לפי חבילה. זה מאפשר מסלול Intel כיום, אך אינו מהווה הסמכת runtime ל־Tahoe 26.7.1 או הבטחת תמיכה עתידית. [פלטפורמות conda-forge](https://conda-forge.org/docs/how-to/advanced/enable-archs/), [מגבלת macOS](https://conda-forge.org/news/2026/02/06/macOS-11/).
- Pixi מתעד `lock` ללא התקנת סביבה, ותומך בדרישות OS דרך virtual packages. יש לייצג את מערכת היעד ביושר, לא להעמיד פנים שהיא ARM64 או OS אחר כדי לקבל פתרון. syntax של דרישות המערכת השתנה; יש להתאים לגרסת Pixi שנבחרה ולשמור גרסת כלי. [Pixi lock](https://pixi.prefix.dev/latest/reference/cli/pixi/lock/), [דרישות מערכת](https://pixi.prefix.dev/latest/workspace/system_requirements/).
- uv מגדיר macOS x86_64 כ־Tier 1 ומינימום macOS 13. יש להשתמש במפורש ב־`x86_64-apple-darwin` וב־Python המתאים בעת בדיקת פתרון; alias כללי ל־macOS עשוי לבחור ARM64. מדיניות no-build ובדיקת כל wheels נחוצות למסלול מוכן. [תמיכת uv](https://docs.astral.sh/uv/reference/policies/platforms/), [CLI](https://docs.astral.sh/uv/reference/cli/), [פתרון לפי פלטפורמה](https://docs.astral.sh/uv/concepts/resolution/).
- MacPorts מציע מתקין Tahoe וארכיוני Darwin 25 Intel שנמצאו במחקר. `port -b` מתועד כמצב בינארי בלבד שעוצר כשארכיון חסר; `-y` הוא חישוב צעדים ללא ביצוע. ה־dry-run לבדו אינו תחליף לבדיקה שכל הארכיונים קיימים ומתאימים. [התקנה](https://www.macports.org/install.php), [ארכיונים](https://guide.macports.org/#using.binaries), [port manual](https://man.macports.org/port.1.html).
- מדיניות Homebrew מסבירה במפורש את מצב Intel ואת חוסר הכיסוי הבינארי המלא של MacPorts ב־Intel Tahoe. לכן אין להציג מעבר כולל ל־MacPorts כפתרון שכבר הוכח. [Support Tiers](https://docs.brew.sh/Support-Tiers).

## חוזה נתונים נדרש לכל חבילה חדשה

כל discovery צריך להחזיר שם מקור וכתובת, זמן איסוף, שם מוצר מול שם חבילת ספק, גרסה upstream ו־revision נפרדים, ארכיטקטורה/OS/ABI, hashes אם פורסמו, אילוצי תלויות, סוג ההתקנה והגבול שמותר להעביר: פקודה, סביבת פרויקט, ספרייה, שירות או נתונים.

לכל מסלול נדרשים מצבים נפרדים: נמצא בקטלוג; נמצא artifact מתאים; תלויות נפתרו; קובץ אומת; הותקן במיקום מבודד; בדיקת תפקוד עברה; נבחר executable; מעבר צרכנים אושר ובוצע. חוסר גרסה או תלות חייב להישמר ככשל/דחייה עם המקור והתאריך. אין להשתמש בגרסה ישנה כדי לסמן את יעד האפליקציה כמעודכן.

לפני שינוי ספק יש להחזיק installation ID קבוע, היסטוריית גרסאות, רשימת aliases/פקודות, בחירת provider פעיל ודרך חזרה. עבור ספריות צריך לתכנן reverse consumers; עבור שירותים צריך לדעת תצורה, launchd, משתמש, פורטים, נתונים ו־extensions. הבחירה יכולה להיות שונה בין שני פרויקטים שמשתמשים באותו מוצר.

הסדר המוצע לגילוי עתידי הוא: קובץ רשמי מוכר ומאומת כשהמוצר תומך בו; Pixi/conda-forge לכלי מבודד או לפרויקט שלם; uv כשיש סגירת wheels מתאימה ל־Python; MacPorts כאשר אפשר להוכיח גרף בינארי שלם. בפועל הבחירה צריכה להיקבע גם לפי גבול המעבר ועלות התחזוקה, ולא לפי ספק ראשון שמחזיר מספר גרסה. כאשר אין מסלול מוכן, התוצאה היא דחייה מוסברת או תכנית בנייה נפרדת; זו תוצאה תקינה של מערכת הגילוי.
