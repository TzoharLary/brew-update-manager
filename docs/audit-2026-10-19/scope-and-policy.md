# גבולות המערכת ומדיניות מוצעת

תאריך: 19.10.2026. מסמך תכנון; אינו משנה את ההתקנות או את מדיניות העדכון הפעילה.

## מה פירוש ״כל החבילות״

המערכת תציג מלאי מאוחד, אך סמכות השינוי תלויה בסוג ההתקנה. גילוי חבילה אינו אישור להעביר אותה לספק אחר, למחוק אותה או לשדרג משפחת גרסאות.

| תחום | גילוי מתוכנן | יחידת עדכון ובעלות |
|---|---|---|
| Homebrew formula/cask | מלאי הספק, קבלות, גרסאות ותלויות | ההתקנה תחת prefix מסוים; לא שם הכלי בלבד |
| כלים עצמאיים של Python/JavaScript | מלאי uv tool / pipx / npm global / Bun, כאשר מותקנים | סביבת הכלי או prefix; תלויות דרך הספק שלה |
| סביבות Pixi/Conda | רישום הספק וסביבות המנהל | סביבת עבודה נעולה, לרבות ספריותיה |
| מנהלי runtimes | התקנות רשומות אצל מנהל גרסאות, אם נמצא | גרסה מותקנת ושיוך לפרויקט בנפרד מברירת המחדל |
| ספריות native ומהדרים | קבלות ותלויות, ובהמשך בדיקות קישור ממוקדות | קבוצת צרכנים תואמת ABI; לא החלפת קובץ dylib בודד |
| שירותים ומסדי נתונים | מנהל החבילות + הגדרת השירות ונתיבי נתונים | חבילה, שירות, נתונים והרחבות כיחידת מעבר נפרדת |
| אפליקציות macOS | casks ומידע bundle/receipt; ספק עדכון אם ידוע | ספק יחיד לכל התקנה; אפליקציה עם מעדכן עצמי אינה משימה כפולה |
| תלויות של פרויקטים | רק תיקיות פרויקט שהוגדרו לסריקה | דיווח תחילה; עדכון במסגרת manifest/lockfile ובדיקות הפרויקט |
| macOS/Xcode ועדכוני מערכת | זיהוי גרסה ומצב תמיכה | הצגת דרישה/קישור למסלול Apple; אינו עדכון חבילת CLI רגיל |
| התקנה ידנית ללא מקור מוכח | נתיב/גרסה/בעלות לא ידועה | הצגה כלא מנוהלת; אין המצאת כתובת הורדה או בעלות |

סריקת פרויקטים לא תעבור אוטומטית על כל תיקיית הבית. קבצי cache וסביבות זמניות אינם התקנות משתמש רק משום שקיים בהם executable. קבלת התקנה ישנה אינה הוכחה שהאפליקציה עדיין קיימת.

## זיהוי חבילות עתידיות

1. בכל בדיקה, הספקים הזמינים מחזירים מלאי חדש. ספק שלא נמצא מסומן כלא מותקן; ספק שנכשל מסומן כלא נבדק ולא כמלאי ריק.
2. חבילה חדשה אצל ספק מוכר מקבלת מזהה הכולל ספק, namespace, scope ונתיב התקנה. היא ניתנת לניהול אצל אותו ספק ללא הוספת שם לרשימת Python בקוד.
3. זהות משותפת בין ספקים נוצרת רק ממיפוי מבוסס מקור, קבלה או אישור מפורש. התאמת שם היא מועמדות לבדיקה בלבד.
4. עדכון רגיל נשאר אצל הבעלים הקיים. מעבר ספק הוא תכנית נפרדת עם פקודות נדרשות, תלויות, בדיקות וסמנטיקת חזרה לגרסה קודמת.
5. חבילה אצל ספק לא נתמך מופיעה עם הסיבה והמגבלה. ״פתרון רוחבי״ פירושו הרחבת מתאמי ספקים, ולא הבטחה לנהל אוטומטית כל התקנה ידנית בעולם.

## איך בוחרים מסלול מתאים למחשב

תחילה מסננים תנאי חובה: החרגות, מקור מאושר, ארכיטקטורה ומערכת הפעלה, טווח גרסאות, תאימות תלויות ונתונים, וסוגי פעולה שהספק תומך בהם. רק בין מועמדים שעברו את הסינון מדרגים נוחות ומהירות.

סדר ההעדפה המוצע: בעלות קיימת תקינה → גרסה נתמכת בתוך המדיניות → קובץ מוכן עם עץ תלויות תואם → הימנעות מהגירה מיותרת → אומדן הורדה/התקנה המבוסס על מדידות. אין לבחור גרסה ישנה, להוריד גרסה ראשית או להרחיב prerelease באופן שקט כדי לקבל התקנה מהירה.

יש להבחין בין: היעדר חבילה מוכנה, פיגור של הספק בגרסה, כשל רשת, פתרון תלויות שנכשל, הגירה שאינה נבדקת, מצב קישור שבור והחרגה. אלה אינם כולם ״נדרשת בנייה מקוד מקור״.

החרגת `ngrok` נשמרת גם בזהות המשותפת וגם ברשומות הספקים הידועות, כולל תלות עקיפה. הופעת שם דומה ממקור לא מוכר לא תבטל את ההחרגה ולא תפעיל התקנה.

## ייעול שניתן למדוד

- אין צורך לחפש חלופות לכל תלות בכל בדיקה. סורקים מלאי, משתמשים בקטלוגים שמורים עם תוקף ברור, ובודקים פתרון רק כאשר גרסה/מדיניות/מחשב/תלויות השתנו.
- מאחדים עבודת תכנון על תלויות משותפות; לא מריצים שוב קומפילציה שנכשלה דרך כל צרכן שלה.
- הורדות ובדיקות metadata עצמאיות יכולות להתבצע במקביל בהגבלה. שינויים באותו prefix, סביבת עבודה או שירות דורשים נעילה.
- שומרים הורדות מאומתות ותכנית עם מזהי artifact. אין לנקות במהלך הריצה קבצים הדרושים לחזרה לאחור.
- מודדים זמן בדיקה, פתרון, הורדה, התקנה ואימות בנפרד; מציגים טווח זמן רק לאחר צבירת מדידות מתאימות.
- מדווחים בנפרד כמה עודכן, כמה נותר עדכני, כמה נדחה וכמה נכשל. משווים זמני ריצה רק עבור אותה קבוצת פעולות; דילוג על עבודה אינו האצה שלה.

## מקורות לתכנון ממשקי הספקים

- [Homebrew support tiers](https://docs.brew.sh/Support-Tiers) — מגבלות תמיכת Intel וזמינות bottles; זמינות חייבת להיבדק מחדש לכל תכנית.
- [uv tools](https://docs.astral.sh/uv/concepts/tools/) — הבחנה בין כלים מותקנים, הרצות זמניות, סביבות מבודדות ואילוצי גרסה הנשמרים בעדכון.
- [Pixi global tools](https://pixi.prefix.dev/latest/global_tools/introduction/) — כלים בסביבות ותיווך פקודות; המנהל הקיים משתמש גם בסביבות workspace פרטיות, ולכן מלאי global לבדו לא מספיק.
- [npm ls](https://docs.npmjs.com/cli/v11/commands/npm-ls/) — מלאי לפי scope ו-prefix; יש לבדוק prefixes נפרדים במקום להניח שמלאי Node הפעיל מייצג את כל ההתקנות.

המקורות נקראו ב־19.10.2026. תכנית זו אינה התחייבות לתמיכת Intel עתידית של ספק כלשהו.
