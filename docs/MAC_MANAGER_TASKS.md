# מנהל עדכוני Mac — משימות והמשך עבודה

עודכן: 25.10.2026. גרסת מקור הפיתוח: 1.3.4; בסיס הסקירה `0a0849b`.
זהו עדכון תיעוד בלבד; האפליקציה המותקנת והחבילות החיות לא נבדקו.

## מצב פיתוח נוכחי — שלב 3 ממומש, שלב 4 הושלם בקוד ובאימות מבודד

**מקור האמת למימוש הוא [דוח מצב 1.3.4](UNIFIED_IMPLEMENTATION_STATUS.md).**
הטבלה, הסעיפים והסימונים ההיסטוריים בהמשך מתארים גם את baseline של 1.3.3; סימון ישן כפתוח **אינו** אומר שקוד לא נכתב, וסימון קוד כהושלם אינו אישור בדיקות קבלה.

| תחום | מצב קוד בענף 1.3.4 | מה עוד נדרש |
| --- | --- | --- |
| T01/T02 | מימושי בסיס נבדקו בעבר ב־1.3.2 | רגרסיות מול הקוד החדש |
| T03 | מנוע מעבר Homebrew→MacPorts, גיבוי, routing, ownership, resume/rollback, ובניית מנוע Pixi קיימים בקוד | בדיקות כשל ושחזור מלאות במסלול Pixi המחובר, קבלה במחשב |
| T04 | גילוי Homebrew/MacPorts/Pixi ממופה גם כשה־Brew הנוכחי אינו מיושן; השוואת גרסאות, חסמים, מגבלת Pixi; מנוע Pixi לפרופילי `jq`/`pandoc` | ל־`jq`/`pandoc` קיימת בחירה מוגנת עם תוכנית עסקה; נדרשים fault-injection וקבלה מלאה |
| T07 | תוכניות שמורות ל־15 דקות, API ו־UI מאוחדים עבור חלק מהפעולות, סקריפט `--checks/--full` כתוב | מסלולי legacy, חוויית 409, תרגומים, רגרסיות ומסירה |
| T05/T06 | המשך אופציונלי וחסמים ספציפיים | מחוץ לשלב הבא |

**ראיות:** [CI #39458648017](https://github.com/TzoharLary/brew-update-manager/actions/runs/39458648017): 63 בדיקות Python ממוקדות, Node לבדיקת תוקף תוכנית, בדיקות תחביר, 37 outputs ב־`unified-check`, אריזה בסיסית. לא ריצת `--checks` מלאה, לא HTTP/Electron, לא בדיקת מוצר על ה־Mac.

### שלבי המשך לביצוע בנפרד עם אישור המשתמש

1. **תיעוד — יושר ב־25.10.2026** מול `0a0849b`; [מפת דרישות ומסירת בדיקות](VALIDATION_HANDOFF.md) מפרידה מימוש, בדיקות קיימות וקבלה פתוחה.
2. **T04: סקירה — הושלמה ברמת ניתוח קוד (שלב 2)** — [דוח מפורט](T04_PROVIDER_DISCOVERY_EXECUTION_PLAN.md#שלב-2--דוח-סקירת-חוזים-ובטיחות-לקראת-חיבור-homebrewpixi) מזהה P0: חסימת bridge, אימות ברירת מחדל MacPorts, ושימור T02 ב־refresh=False; אין שינוי במימוש.
3. **T04: חיבור — הושלם ברמת קוד (שלב 3)** — `ready` נוצר רק למסלול Pixi עם פרופיל `jq`/`pandoc` ותוכנית עסקה מאומתת; בדיקות קבלה עדיין פתוחות.
4. **T03/T04: ביצוע — שלב 4 הושלם בקוד ובאימות מבודד (25.10)** — [דוח מסירה](STAGE4_RECOVERY_VALIDATION.md): שחזור מקור/ניתוב/בעלות, חלונות קריסה, ביטול/timeouts, בקשת העדכון ו־HTTP/UI. 100 בדיקות Python ו־8 תרחישי UI עברו; קבלת חבילות חיות נפרדת.
5. **T04: בחירה — השלב הבא** — רגרסיות השוואה, completeness ושמות ספקים.
6. **T07: API** — צמצום נתיבי legacy ועקיפות.
7. **T07: UI** — הסרת אשף כפול ויישור נימוקים, סיכומים ושגיאות.
8. **בדיקות** — Python, HTTP/Electron, כשלי מערכת ו־fixtures מבודדים.
9. **מסירה** — גנרטור, bundle, manifest, pack/install מבוקרים.
10. **ביקורת** — בדיקת diff, גבולות בטיחות, תיעוד והכנה לקבלת משתמש.

**כללי עצירה:** אין מעבר חבילות אמיתי, התקנה/הסרה, שינוי PATH, הפצת release או מיזוג ל־`main` במהלך צעדי הקוד. המסלול `--full` קיים אך אינו אישור להרצה בלי סיום פיתוח ובדיקה.

## המטרה המחייבת

בדיקה אחת → בחירת ספק אוטומטית לפי חבילה מוכנה וגרסה מתאימה ל־Mac Intel →
בחירת חבילות → לחיצה על עדכון → ביצוע ושמירת הספק החדש לאחר מעבר מוצלח.
המעבר הוא חלק מהעדכון המוצג למשתמש, בלי אישור נוסף לכל חבילה.

[מטרת המוצר והחלטות העבודה](PRODUCT_GOAL.md) היא המסמך המחייב.
[תיעוד המימוש](MAC_MANAGER.md) מתאר את הקוד הקיים והפערים מול המטרה.
אין לפרש קיום קובץ או API כהשלמת מעבר אמיתי, שחזור או חוויית העדכון הרצויה.

## החלטות עבודה

- Intel, חבילות בינאריות וכל תלויותיהן; בלי נפילה לבניית מקור או ירידה בגרסה.
- Homebrew, MacPorts, Pixi לפי התאמה. בשוויון לשמר ספק; לבחור גרסה חדשה
  מתאימה ממסלול נתמך ולבדוק מחדש חלופה כשהספק הקיים אינו נותן מענה.
- לחיצת עדכון מאשרת את הפעולות המוצגות, כולל מעבר ספק. דרישת הרשאת macOS
  כשנחוצה אינה אישור מעבר נוסף שהאפליקציה צריכה להמציא.
- לשמור ngrok מוחרג, הגדרות, היסטוריה, תזמון וזהות התראות. לא לחפש פרויקטים
  פרטיים; אפשרות לסקריפט פרטי אינה חסם. תלויים מתועדים ושירותים דורשים טיפול.
- כל שינוי מוצר, בדיקות ותיעוד מופק דרך `tools/implement-mac-manager.py`;
  את הסקריפט עורכים ב־apply_patch. כל פקודות הטרמינל בסשן אינטראקטיבי.
- לשמר את העבודה הלא מחויבת והגיבויים. אין להפעיל apply/document-tasks ישנים
  כדי לתקן תיעוד, ואין לאפס README או מניפסט קודם בגלל כשל תנאי קדם.
- הסוכן יבצע אימות קצר וממוקד בלבד; המשתמש יריץ את הבדיקות המלאות בסקריפט.
  הוראה זו מחליפה את החלוקה הישנה שבה הסוכן הריץ הכול והמשתמש רק פיילוט.
